# Fracode MCP — долговременная память для агентов за 24 байта на токен

[Русский](README.md) | [English](README.en.md)

Это моя реализация внешнего long-term memory для LLM-агентов: весь архив разговоров
и кода лежит в сжатом виде, агент достаёт из него контекст по MCP, а не перекачивает
историю в промпт.

## Откуда идея

Я год гонял микро-модель (STS-Prog, ~11M параметров) на сжатии последовательностей —
эксперимент в этом же репо, ветка `pc-carroll`. Модель обучалась предсказывать
следующий токен через синхронные драйвер-слои, и побочный продукт её работы —
компактная таблица эмбеддингов токенов — оказалась пригодной как ключ поиска.
То есть память выросла из модели, которая учится сжимать, а не из векторной базы,
которая учится искать.

## Зачем

Контекстные окна платные, и агенты платят за них повторно каждый запрос. Векторные
базы для памяти — это внешние тяжёлые сервисы с эмбедером на миллиарды весов. Я
хотел, чтобы память агента стоила дёшево: один файл, никакой записи через LLM,
поиск за десятки миллисекунд, и чтобы работало локально.

## Что это даёт (реальные цифры)

Бенч на общем срезе моей рабочей истории (2.9M токенов диалогов, 313 вопросов с
известными ответами-иглами), против RAG (chroma) и Mem0, одна и та же чат-нода:

![bench](bench_chart.png)

| | recall@4 | токенов в промпте | поиск | LLM-токенов на запись |
|---|---|---|---|---|
| без памяти | 0.00 | 151 | — | 0 |
| RAG (chroma) | 0.24 | 263 | 27 мс | 0 |
| Mem0 | 0.08 | 684 | 63 мс | 1 686 418 |
| **Fracode** | **0.84** | 560 | 41 мс | **0** |

Хранилище: 24 байта на токен архива. Никаких внешних БД, никаких LLM-вызовов
на инжест — архив строится из текста за минуты на CPU.

## Как устроено

1. **Архив** — BPE-токенизированный текст, разбитый на окна; каждое окно
   кодируется квантованием (product-quantizer на эмбеддингах микро-модели)
   в кодовую последовательность. `frakod_index_build.py`.
2. **Поиск** — век ADC-скрининг кандидатов по квантованным ключам +
   лексический exact-слой: редкие слова запроса ищутся точными
   последовательностями токенов по id-массиву архива, с IDF-ранжированием.
   Гибрид (`/recall`, режим auto) даёт и семантику, и точность слов.
   `frakod_api.py`.
3. **MCP** — stdio-сервер `frakod_mcp.py` с семью инструментами
   (`remember`, `link`, `resolve`, `chain`, `recall`, `ask_llm`, `index_stats`).
   Подключается в любой MCP-клиент строкой:
   `{"mcpServers": {"frakod": {"command": "python", "args": ["frakod_mcp.py"]}}}`
4. **Переносимость истории** — `ingest_chat.py` импортирует выгрузки диалогов из
   других агентов (форматы `a`/`b`/jsonl/txt) в тот же архив: забираешь историю
   у одного агента, ищешь через другого.

## Быстрый старт

```bash
pip install -r requirements.txt
# 1) построить архив из своего текста
FRK_CORPUS=my_history.txt FRK_OUTD=frakod_index python frakod_index_build.py
# 2) поднять API (порт 8781)
python -m uvicorn frakod_api:app --port 8781
# 3) подключить MCP-клиент к frakod_mcp.py
```

## Почему круто

- Память стоит **24 Б/токен** и не требует базы данных.
- Запись **бесплатна**: ни одного LLM-вызова на инжест (у Mem0 на тот же корпус
  ушло 1.7M токенов и 31 минута).
- recall@4 0.84 на диалогах — в 3.5 раза лучше классического RAG на том же корпусе.
- Всё локальное, лицензия GPL-3.0, читается за один вечер: ~1.5k строк python.
