# Fracode MCP — долговременная память для агентов

[Русский](README.md) | [English](README.en.md)

Внешняя долговременная память для LLM-агентов. Архив разговоров и кода лежит
на диске в сжатом виде, агент достаёт из него нужный контекст по MCP — вместо
того чтобы перекачивать всю историю в промпт на каждом запросе.

## Откуда идея

Микро-модель (STS-Prog, ~11M параметров) обучалась сжатию последовательностей —
эксперимент в этом же репо, ветка `pc-carroll`. Модель предсказывала следующий
токен через синхронные драйвер-слои, и побочный продукт — компактная таблица
эмбеддингов токенов — стал ключом поиска. Память выросла из модели, которая
учится сжимать.

## Сколько занимает память

Два независимых механизма, их важно не смешивать:

| | Архив (`codes.npy`) | Оперативная память (`/remember`) |
|---|---|---|
| Что хранит | 24 Б/токен кодов + keys для реранка | текст записи целиком |
| Запись | офлайн-сборка из корпуса | во время работы агента |
| Сжимает | да | нет |
| Файл | `frakod_index/*.npy` | `frakod_store.json` |

**«24 Б/токен» относится к `codes.npy`** — это само сжатие, и на нём работает
ADC-скрининг кандидатов. Полный след архива на диске больше, потому что для
точного реранка читаются `keys_f16.npy`, а для лексического слоя — `ids.npy`:

```
N = 2 927 882 токена
codes.npy     =   67.0 МБ    24.0 Б/токен   ← это и есть «24 Б»
keys_f16.npy  = 1072.2 МБ   384.0 Б/токен   ← реранк кандидатов
ids.npy       =   11.2 МБ     4.0 Б/токен   ← лексический exact-слой
-------------------------------------------------------------
итого         = 1150.8 МБ   412.1 Б/токен
```

`keys_f16` можно держать не резидентно: реранк читает их `mmap`-ом с диска.
Без него постоянный след — 28 Б/токен на токен архива.

Размер кода: `24 Б/токен` — это **d=192, S=12**. Другие конфигурации дают
другой код: при d=256, S=16 код — `(N,2,16)` = 32 Б/токен. Выбор
«дешевле/точнее» осознанный.

## Как быстро и точно ищет

Один архив, одни вопросы, разные каналы поиска — `test_24b_proof.py`.
Архив на v7: BPE-8192, d=256, S=16, N=2 386 967 токенов.

| канал поиска | recall@4 | медиана |
|---|---|---|
| ADC по кодам, запрос-вопрос | 0.30 | 638 мс |
| коды + реранк `keys_f16`, запрос-вопрос | 0.60 | 49 мс |
| лексический exact-слой | 1.00 | 17 мс |
| гибрид (`auto`) | 1.00 | 64 мс |
| ADC по кодам, запрос-сниппет | 0.00 | 648 мс |
| коды + реранк, запрос-сниппет | 0.17 | 53 мс |

`recall@4` = «слово-игла встречается в тексте любого из 4 вернувшихся окон».
Строгий precision@4 лексического слоя — 0.25 на вопросах, 0.29 на сниппетах.

Как это читать: 24-байтовый ADC находит кандидатов (0.30), реранк по
`keys_f16` поднимает до 0.60. Гибрид добирает до 1.00 лексическим точным
поиском по `ids.npy` — это инвертированный индекс по редким словам. На
коротких сниппетах без шаблона вектор почти не работает (0.00–0.17):
усреднённое окно размывает короткий запрос.

## 24 Б/токен на код-архиве

Архив `frakod_index_code10m` — 10 000 000 токенов кода, BPE-8192. Истинная
позиция искомого фрагмента известна, метрика — попадание в ±7 токенов.

| метод запроса | top-1 | top-4 | cos |
|---|---|---|---|
| контекстный запрос, окно RAD=4 (как в билдере) | 14/16 | 14/16 | 1.000 |
| монотокенный запрос `E[ids].mean(0)` | 8/16 | 8/16 | 0.958 |

Сквозь живой API на том же архиве, 16 позиций из 10 млн, ADC по 24 байтам:

| канал | top-1 | top-4 | top-8 |
|---|---|---|---|
| ADC только по 24 Б | 0/16 | 3/16 | 7/16 |
| 24 Б + реранк по `keys_f16` | 0/16 | 3/16 | 7/16 |

7 из 16 запросов попадают в ±7 токенов, выбирая 16 кандидатов из 10 000 000 —
в 625 000 раз плотнее случайного. 24-байтовое сжатие несёт рабочую информацию.

## Бенч против RAG и Mem0

Срез истории, 30 вопросов с иглами (реально использовано 25 после
дедупликации), одна чат-нода. Артефакт — `bench_results.json`, воспроизведение —
`bench_memory_systems.py`.

| | recall@4 | токенов в промпте | поиск | LLM-токенов на запись | хранилище |
|---|---|---|---|---|---|
| без памяти | 0.00 | 151 | — | 0 | — |
| RAG (chroma) | 0.24 | 263 | 27 мс | 0 | 20.3 МБ |
| Mem0 | 0.08 | 684 | 63 мс | 1 686 418 | — |
| **Fracode** | **1.00** | 560 | 17 мс | **0** | **1150.8 МБ** |

Честные оговорки:

- **Запросы у систем разные.** RAG и Mem0 получают короткий вопрос; Fracode в
  исходном бенче получал 160-символьный фрагмент, содержащий искомое слово
  дословно. Теперь бенч считает оба протокола; в таблице выше — равные условия
  (`query`).
- **Fracode берёт числом за счёт лексического слоя**, а не вектора. Это
  ожидаемо для задачи «редкое слово встречается в корпусе один раз».
- **Mem0 решает другую задачу** — извлекает структурированные факты через LLM,
  отсюда 1.68M токенов записи. Это честная цена LLM-инжеста.

## Как устроено

1. **Архив** — BPE-токенизированный текст, разбитый на окна; каждое окно
   кодируется product-quantizer'ом на эмбеддингах микро-модели.
   `frakod_index_build.py`.
2. **Поиск** — ADC-скрининг кандидатов по 24-б кодам, реранк по `keys_f16`,
   плюс лексический exact-слой (редкие слова запроса ищутся точными
   последовательностями токенов по `ids.npy`, IDF-ранжирование).
   Гибрид — `/recall`, режим `auto`. `frakod_api.py`.
3. **MCP** — stdio-сервер `frakod_mcp.py`, 8 инструментов: `remember`, `link`,
   `resolve`, `chain`, `recall`, `recall_vector_only`, `ask_llm`, `index_stats`.
   Адреса — `frk1:<slot>.<id>`, `link`/`chain` принимают и адрес, и голый id.
   ```json
   {"mcpServers": {"frakod": {"command": "python", "args": ["frakod_mcp.py"]}}}
   ```
4. **Переносимость истории** — `ingest_chat.py` импортирует выгрузки диалогов из
   других агентов (форматы `a`/`b`/jsonl/txt) в тот же архив.

## Быстрый старт

```bash
pip install -r requirements.txt
# 1) построить архив из своего текста
FRK_CORPUS=my_history.txt FRK_OUTD=frakod_index python frakod_index_build.py
# 2) поднять API (порт 8781)
python -m uvicorn frakod_api:app --port 8781
# 3) подключить MCP-клиент к frakod_mcp.py
```

Для векторного канала нужен чекпойнт эмбеддера; для лексического — корпус
(тот же, что кодировали). Путь задаётся `FRK_CORPUS`, иначе ищется рядом с
пакетом.

## Почему это круто

- **Запись бесплатна**: ноль LLM-вызовов на инжест — в отличие от схем, где
  каждый факт прогоняется через модель.
- **Память на диске в 16 раз компактнее ключей**: 24 Б/токен кодов против
  384 Б/токен f16 — и эти 24 байта реально несут информацию для поиска.
- **Гибрид даёт recall@4 1.00** при медиане ~64 мс на 2.4M токенов: вектор
  приводит кандидатов, лексический слой добивает точно.
- **Работает как обычный MCP-сервер** — подключается к любому агенту, память
  живёт рядом с моделью, а не внутри неё.
- **Всё локальное**, GPL-3.0, ~1.5k строк python. Никаких внешних API.
